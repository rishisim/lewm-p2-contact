**Blocking changes**

1. **Separate role effects from distribution shift.** In [PLAN.md](/Users/rishisim/Documents/research/lewm-p2-contact/experiments/role_swap/PLAN.md), R2 relocates the peg, while R3 changes the manipulated object, goal, and agent-goal geometry. Pairing base IDs does not control these differences. Likewise, `ft_mixed` changes placement, policy, contacts, and motion simultaneously; improvement establishes broader coverage, not specifically role learning. Add matched starts with different task objectives and hold placement distributions fixed across training arms. Otherwise narrow the claim to *generalization across manipulation tasks and interaction coverage*. Define whether R1 genuinely ignores the peg: requiring “unmoved” makes it another preservation task.

2. **Fix environment state, reset, and termination together.** S’s `envs/pusht/env.py` computes proprio using `state[-2:]` in **both `reset()` and `step()`**, and goal proprio similarly in `_get_info()`. Appending peg xy therefore requires more than the listed overrides: update reset, observation space, goal proprio, and body creation in `_setup()`. `_set_state()` advances physics and does not restore block velocity/angular velocity; a nine-value observation is insufficient for faithful simulator cloning. Implement separate complete snapshots and test identical future rollouts after restoration. `_set_goal_state()` only assigns state; it does not regenerate `_goal` or update `goal_pose`. Render goals explicitly without disturbing the live simulation.

3. **Integrate role success into execution.** S’s `world/world.py::World.evaluate()` derives success from `terminated`, not an arbitrary role metric. Keeping native `eval_state()` can stop R3 immediately when agent/T match their starting goal, irrespective of the peg. Use role-aware termination or a controlled evaluation loop; specify terminal versus ever-achieved success. For “don’t disturb,” final displacement permits moving the peg away and back—use maximum trajectory displacement if disturbance is prohibited. `World.collect()` also ends episodes on termination; configure collection so “100 steps” means what the protocol assumes.

4. **Specify a compatible software stack and fine-tuning path.** U’s `config/eval/solver/cem.yaml` targets `stable_worldmodel.solver.CEMSolver(model=...)`; inspected S exposes `planning.solver.CEMSolver(cost=...)`. Compose `ShootingCostEvaluator(model, GoalMSE())`. Current [le-wm/eval.py](/Users/rishisim/Documents/research/lewm-p2-contact/le-wm/eval.py) also uses `policy.AutoCostModel`, absent from inspected S. Pin the exact compatible source revision/artifact; version `0.1.1` alone does not establish clone/wheel equivalence. S’s declared extras put Lance under `[data]` and HDF5 dependencies under `[format]`, missing from the proposed install. U’s `train.py` instantiates `jepa.JEPA` from scratch: add explicit pretrained loading, checkpoint compatibility checks, and reload parity. Split training/validation by episode before overlapping windows.

5. **Make action semantics and normalization explicit.** S’s `data/dataset.py` groups five consecutive 2-D actions into a 10-D block; `policy.py` executes them separately. Thus horizon 5/receding 5 means planning and executing **25 environment steps**, not replanning every five. Match this across oracle, A/B/C, and training. Persist each checkpoint’s training normalization; fitting a new scaler for pretrained evaluation changes its input semantics. For cross-arm comparisons, share candidate banks in physical action coordinates and transform separately per model.

6. **Do not call weak readout or poor B–C agreement encoder loss.** S’s `wm/lewm/lewm.py::encode()` has distinct CLS and projected representations. Probe both on one common, episode-disjoint evaluation distribution, with grouped inner CV and pixel-error baselines. Peg/T R² values reflect different target variances and visibility; they are not directly comparable evidence of retention. Poor B–C agreement identifies a representation/**cost** mismatch. Strong peg readout plus poor B–C supports cost failure; weak linear readout establishes only weak linear accessibility. Freeze numerical definitions for “well below” and “materially.”

7. **Repair oracle normalization and candidate-bank inference.** Finite-budget simulator CEM is a reference planner, not an optimality oracle. Define the normalization formula; role-specific oracle-solved subsets break cross-role pairing. Use an independently selected common feasible set, report exclusions and unconditional outcomes, and cluster bootstrap by base episode. Freeze physical-unit cost weights. Share banks across arms, deduplicate elites, and require both successful and unsuccessful candidates plus meaningful C variation; “best candidate succeeds” alone is insufficient. Obtain elites through S’s CEM callbacks—the standard return contains the optimized mean, not an elite bank.

8. **Pilot compute before scaling.** Oracle settings imply `300×30×25×2 = 450,000` environment steps, approximately **4.5 million physics substeps per episode**; 600 episodes approach 2.7 billion substeps. Benchmark simulator rollout, MPS planning, and training separately. Planning throughput cannot set a six-hour training budget. Start with tiny collection/backward/checkpoint/planning tests; measure peak unified memory and loader pressure. Choose evaluation N using pilot paired discordance and power, count feasible bases, and include independent training seeds—or explicitly limit conclusions to one checkpoint.
